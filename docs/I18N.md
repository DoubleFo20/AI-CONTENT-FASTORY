# TH/EN localization contract

Thai (`th`) is the default; English (`en`) is the only additional V1 locale. A small typed
dictionary requires identical keys, preventing partial locale coverage. Public locale
preference alone may be stored in localStorage; private projects/tokens must not be.
Set document.lang; use Intl.DateTimeFormat/NumberFormat for locale-aware display.

Translate navigation, setup/login, forms, buttons, placeholders, validation/error messages,
queue statuses, progress, empty states, offline notice, file-import instructions and export
states. Server errors use stable codes; the client maps codes to both locales, not raw
provider/OS errors. Backend content schemas use {th,en}; switch content by current locale.
Technical IDs and model names remain proper identifiers; no English-only product chrome.

Thai scene explanations and English Google Flow prompts intentionally remain in their
specified languages regardless of UI locale. Label that distinction in both locales. Never
translate an English Flow prompt implicitly or alter its continuity references. Support
Thai line breaking, long English labels, keyboard interaction and a 44px locale switch.

Coverage validation compares dictionary keys, verifies known error codes, confirms document
language and renders critical setup/login/story/queue screens in both locales. Translation
coverage does not replace browser layout checks at 360/768/1440px or native-language review.
